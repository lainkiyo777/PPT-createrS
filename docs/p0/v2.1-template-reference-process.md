# v2.1 模板参考型 PPT 生产复盘与契约

## 结论

这次用户认可的版本不是“把模板源页复制后替换文本”，而是：模板提供蓝色品牌视觉语言，逐页 prompt 让图片模型根据新能源集控答辩内容重新构图；模型生成 14 张预览图，审核后按正确页码全幅插入 PPTX。v2.1 将这条路径作为模板参考型任务的可运行回归路线。

## 实际执行顺序

1. 从模板 PPTX 导出 `reference-slides/source-slide-01.png` 至 `source-slide-14.png`，保留每页的蓝白色、深蓝标题带、细线、卡片、图表和工程科技语汇。
2. 对原内容做逐页文字清单，禁止改写关键数字和结论；输出 `source-text-inventory.md`。
3. 为每页建立独立 prompt。prompt 先声明参考对应模板页的视觉语言，再声明不复制模板原文字和精确文本框坐标，最后说明本页的语义构图（模型结果比较、架构图、流程图、时间线、指标卡等）。
4. 通过 Codex 宿主的实际 `image_gen` 逐页调用，参考对应 `source-slide-XX.png` 生成 14 张 `slide-XX-preview.png`；工具版本、参考图和输出文件须记录。
5. 生成联系表进行整套预览审核，重点检查页码顺序、文字层级、信息密度、图表/架构可读性和模板风格一致性。只在 slide spec/prompt 层返工，不直接修改合成器排版。
6. 预览通过后，正式模式应使用同一规格和参考图重新生成 `final-images/slide-XX.png`，保持信息结构不变。临时示例可使用已审核预览作为示例 deck 的图片源，但报告必须明确这是退化路径。
7. 用 PPT 合成器创建空白 16:9 deck，每页只插入对应的全幅图片并写入 notes；不得在 PPTX 中重新排正文、表格或图表。
8. 重新打开/渲染 PPTX，校验 14 页、14 张图、16:9、页码顺序、notes 和单图铺满结构。

## v2.1 防退化规则

- 上传模板不等于用户选择 strict-template；默认 `style-reference`。
- `style-reference` 不允许全套 duplicate-slide，不允许源页文本框尺寸限制新正文容器。
- 内容语义优先：比较页可新增图表，架构页可新增节点和箭头，信息过载时改构图或拆页。
- 没有 `style-profile.yaml`、逐页规格、预览审核记录或实际图片生成器证据时，不得进入整套图片生成/合成。
- 不可用图片工具时明确失败并输出 prompt 和任务清单，不伪造生成结果。
- 最终 PPTX 只做图片全幅铺入；所有视觉修改回到 preview/final image 阶段。

## 已知示例限制

示例第 14 页的图片模型曾把页脚中的页码文字误生成为“9”；PPTX 页序本身仍为 01–14。该缺陷保留在复盘中，提醒 v2.1 的 QA 必须检查图片内关键页码和数字，不能仅检查文件名或 PPTX 顺序。
